dictate — end-to-end flow

One binary, one config story: ~/.config/dictate/.env + text.toml. DICTATE_PROFILE decides what “kind of session” you get. The recommended shortcut pair is live typing on SUPER,R and smart paste on SUPER+SHIFT+R.

1. Startup (every invocation)

  1. Parse CLI: optional --daemon, --stream, --pipe-to, --dictation-mode, subcommands (config, history, scratchpad, …).
  2. Load .env → Config::from_env() (provider, keys, DICTATE_PROFILE, overlay, context limits, …).
  3. Load text.toml beside it → dictionary, snippets, cleanup, [polish], [history], [command_mode].
  4. Legacy override: --mode live|smart maps to live_typing / smart_paste only.
  5. Resolve output: CLI --pipe-to wins, else SHORTCUT_OUTPUT in .env (type / paste / clipboard / stdout).

2. The big router (main.rs)

After config load, exactly one audio/STT loop runs:

┌─────────────────────────────────────┐ │ args.daemon && use_realtime ? │ │ use_realtime = mistral realtime │ │ AND profile ≠ command │ └──────────────┬──────────────────────┘ yes │ no ┌──────────────▼──────────────┐ │ Mistral WebSocket daemon │ ┌────────────────────────────┐ │ (segmented or live_typing) │ │ daemon OR smart_paste OR │ └──────────────────────────────┘ │ command profile ? │ └─────────────┬──────────────┘ yes │ no ┌──────────────────▼─────────────┐ │ Clip daemon (toggle record) │ │ SIGUSR1 start/stop → STT clip │ └──────────────────┬─────────────┘ else │ ┌──────────────────────────────────────────────▼──────────────┐ │ --stream OR use_realtime (non-daemon) → realtime until SIG │ └──────────────────────────────────────────────┬──────────────┘ else │ ┌──────────────────────────────────────────────▼──────────────┐ │ One-shot clip: record until SIGUSR1 → transcribe → exit │ └─────────────────────────────────────────────────────────────┘
ProfileTypical launchRouter branch
live_typing dictate --daemon --mode live Mistral realtime daemon; raw deltas typed while you speak
smart_paste dictate --daemon --mode smart Clip daemon: record → whole clip STT → one Mistral polish → paste
segmented dictate --daemon + shortcut Mistral realtime daemon; segments finalized with polish + voice edits
batch_clip One-shot shortcut without --daemon One-shot clip; local text processing only
command dictate config set profile command + --daemon Clip daemon; STT text = instruction, not document text

Shortcut behavior: generated shortcuts match the exact daemon command they launch, so live_typing, smart_paste, and segmented daemons do not steal each other’s SIGUSR1 toggles. live_typing waits for the first shortcut press, then streams typed deltas while active.

3. Realtime WebSocket path

Mic → Mistral realtime WebSocket → events:

  • transcription.text.delta — typed immediately in live_typing; previewed only in segmented.
  • transcription.segment — in segmented, one finished phrase → emit_finalized_segment().

Per segment (segment_output.rs)

  1. Trim empty; overlay → Processing.
  2. Intent on raw STT (intent.rs): insert vs “scratch that”, delete line, replace X with Y, reset context, …
  3. If insert + segment polish enabled: local cleanup → optional polish_segment() (Mistral chat, prior session window) → text to insert.
  4. Context session (context_session.rs): plan_edit + apply_edit on a TranscriptBuffer (tracks what was typed; backspace via ydotool when editing).
  5. Output via OutputBackend: stdout or --pipe-to (usually ydotool type).
  6. Append line to local history if [history] enabled in text.toml.
  7. Beeps + overlay back to Listening.

Controlled by CONTEXT_EDITING in .env for non-segment paths; segmented always uses the buffer + intents for finalized segments.

4. Clip daemon path (smart_paste, command, optional segmented without realtime)

Same loop in run_daemon_clip_mode:

  1. Load STT provider once (Mistral / Groq / local).
  2. SIGUSR1 while idle → start recording (beep, overlay Listening).
  3. SIGUSR1 while recording → stop → WAV → run_clip_transcription().

Inside finalize_transcribed_text

if profile == command:
    run_command_mode(transcript, clipboard, text.toml [command_mode])
else if profile == smart_paste:
    local cleanup → polish_transcript (Mistral)
else:
    local cleanup (+ developer dictation mode)

5. Clipboard commands (same shortcut — auto)

You should not switch profiles or remember a second shortcut. On every segment/clip, dictate peeks the clipboard:

  • Clipboard has real text (≥12 chars) and you said something short/instruction-like (“fix grammar”, “make this concise”) → clipboard command (transform selection, output via pipe).
  • Otherwise → normal dictation (polish + voice edits).
  • “Scratch that” / delete intents never become clipboard commands.

DICTATE_PROFILE=command only forces clipboard-command behavior. Normal dictation profiles can auto-detect short clipboard instructions when that path is enabled.

7. Shortcut pattern (compositor)

pgrep -f '[d]ictate --daemon --mode live --pipe-to ydotool type --file -' >/dev/null \
  && pkill -f --signal SIGUSR1 '[d]ictate --daemon --mode live --pipe-to ydotool type --file -' \
  || (dictate --daemon --mode live --pipe-to ydotool type --file - &)

First press starts the matching daemon; later presses toggle that same daemon. The [d]ictate regex avoids matching the shortcut’s own shell process. Generated by dictate shortcuts hyprland --profile live_typing --mode type --key SUPER,R.

8. Files on disk

  • ~/.config/dictate/.env — profile, provider, keys, shortcut output, overlay
  • ~/.config/dictate/text.toml — dictionary, snippets, polish, history, command_mode
  • ~/.local/share/dictate/history.jsonl — optional transcript log
  • ~/.local/share/dictate/scratchpad.md — optional notes

Source map: main.rs (router), streaming.rs (realtime/VAD), segment_output.rs (segmented finalize), clip_pipeline.rs (clip STT), profile.rs (DICTATE_PROFILE), context_session.rs + intent.rs (voice edits).
